# 多序列 Marker–ORB 米制 Atlas：设计与后续实现记录

> 状态：概念设计，尚未实现。  
> 目标场景：工厂、实验室、家庭工位中的低负担 ego 机器人示教采集。  
> 核心思想：多个无需时间同步的单目视频，通过静态 marker、ORB 场景重叠和分层几何验证，共同构建一张可复用、可更新的米制 Atlas。

## 1. 问题与目标

单段单目 SLAM 容易因视角不足、纹理稀少、手和操作物体遮挡、运动模糊或长距离转场而失跟。单次建图也只能保存有限角度和距离下的 ORB 描述子，换一个操作者、相机位置或观察方向后，既有地图点可能无法匹配。

本方案不要求一段视频独立完成整个场景建图，而是允许不同操作者、不同相机、不同时间录制的多个序列持续贡献观测：

- 静态 marker 提供米制尺度、跨序列关联和可靠的初始地图变换；
- ORB 自然特征验证真实场景重叠，并补充 marker 不可见区域；
- 已经粗略对齐的相机轨迹只用于缩小候选搜索范围；
- 跨帧、跨序列持久性用于区分长期静态点和会话局部/动态点；
- 局部 BA、子地图位姿图和周期性全局 BA 保持整张 Atlas 一致；
- 后续动作视频优先在已有 Atlas 中定位，而不是每次从零建图。

目标不是声称“单目永不失败”，而是提高以下指标：

1. 新序列的首次定位成功率；
2. 世界坐标位姿有效率；
3. 失跟后的重定位速度；
4. 不同视角、不同操作者和不同相机之间的地图复用能力；
5. 相机与双腕米制动作标签的最终有效产出率；
6. Atlas 长期积累时的尺度、内存和计算成本可控性。

## 2. 明确边界

### 2.1 本方案做什么

- 多段独立单目视频的离线/增量协同建图；
- marker 辅助的米制初始化、尺度恢复、跨序列合图和再锚定；
- ORB place recognition、几何验证和跨序列地图点融合；
- 轨迹邻近引导的局部候选搜索；
- 无学习网络的动态/不稳定地图点筛选；
- 多相机独立内参以及可选的机会式 marker 自标定；
- 工位级局部地图和全局 Atlas 的分层维护。

### 2.2 本方案不承诺什么

- 当前帧严重模糊、过曝或完全无纹理时仍能可靠定位；
- 没有共同 marker、没有自然特征重叠的地图可以强行合并；
- 仅凭轨迹空间接近就确认两个地点相同；
- 一个当前完全静止的可移动物体能立刻被视觉识别为动态物体；
- 单次平面 marker 观测可以精确完成全部相机内参和畸变标定；
- 腕带 marker 可以作为静态地图锚点。

## 3. 核心原则：证据必须分级

跨序列关系必须由强证据向弱证据逐级建立，候选关系不能直接写入正式 Atlas。

| 证据 | 角色 | 是否可独立提交地图合并 |
|---|---|---:|
| 多帧可靠观察到同一个已登记静态 marker | 强关联、米制尺度、初始变换 | 可以提出强候选，但仍需残差验证 |
| ORB BoW 相似 + 2D/3D 几何一致 | 场景重叠和视觉回环 | 可以 |
| marker 与 ORB 同时支持 | 最高置信度跨序列连接 | 可以 |
| 已对齐后的轨迹空间接近 | 缩小搜索范围 | 不可以 |
| 不同 ID 但尺寸相同的 marker | 无关联信息 | 不可以 |
| 两条轨迹看起来相似 | 弱启发式 | 不可以 |

关键规则：

> marker 和轨迹负责提出候选，ORB 几何与多帧 marker 残差负责确认；任何候选只有通过统一验证后才能原子提交。

## 4. 坐标系、尺度与身份

### 4.1 坐标系

- 每个视频序列最初拥有自己的 `session frame`；
- 每张局部地图拥有自己的 `submap frame`；
- 每个已合并 Atlas 拥有唯一 `atlas world frame`；
- 同一个 Atlas 内，marker world 与 Atlas world 必须是同一坐标系；
- 输出动作标签必须记录 `atlas_id`、`map_id`、`map_revision` 和 `metric_state`。

### 4.2 尺度状态

每张地图只能处于以下状态之一：

- `arbitrary-scale`：普通单目初始化，尺度未知；
- `metric-pending`：出现尺度候选，但观测数量或基线不足；
- `metric`：已通过 marker 尺度验证；
- `lost`：当前无法定位，不得冻结或插值成有效测量。

地图合并变换：

- 两张已经米制的地图：使用 `SE(3)`；
- 至少一张任意尺度地图：使用 `Sim(3)`，验证后再转为米制；
- marker 物理边长永远不缩放；
- 已经米制的手部相机坐标不能被重复应用尺度。

### 4.3 Marker 身份管理

- 同一 Atlas 内，一个静态 marker ID 只能对应一个物理位置；
- 相同 ID 贴在多个地方会造成灾难性错误合图，必须在部署工具中阻止；
- 腕带 marker 单独登记为 `dynamic body marker`，永远不进入静态 Atlas；
- 未知静态 marker 可通过视觉轨迹逐步登记，但不同 ID 本身不表示空间关联；
- 相距很远、从未通过视觉轨迹或共同观测连接的 marker 保持独立，不能预设相对位置。

## 5. 系统总体结构

```text
不可变原始视频（多相机、多操作者、多时间）
                    ↓
        每序列观测缓存（只分析一次）
        marker / ORB / hand / QC / calibration hints
                    ↓
          每序列局部 SLAM / 子地图
                    ↓
       跨序列候选生成（marker → BoW → trajectory gate）
                    ↓
       几何验证与初始 SE(3) / Sim(3)
                    ↓
       子地图位姿图优化 + 局部联合 BA
                    ↓
       跨序列静态一致性判断与地图点整理
                    ↓
             再匹配 / 再优化 1–2 次
                    ↓
      可复用的米制 Atlas + 版本化事件日志
                    ↓
        新动作视频定位与最终动作标签生成
```

## 6. 分阶段算法

### 阶段 A：视频接入与相机模型

每个输入序列保存：

- 原始文件指纹；
- 相机设备/镜头/分辨率/裁剪模式标识；
- 标定文件及不确定性；
- 帧时间戳和实际 FPS；
- 曝光、白平衡、防抖、旋转和编码信息；
- marker、ORB、手部与质量检测缓存。

不同相机不需要相互外参，但必须各自拥有有效内参。后续可增加机会式 marker 自标定：

1. 用标称 FOV 和图像中心建立粗内参；
2. 利用不同距离、倾角和画面位置的固定 marker 四角积累观测；
3. 优化 `fx, fy, cx, cy` 和必要的畸变参数；
4. 内参不确定性达到阈值后锁定；
5. 用最终内参重新离线处理整段序列。

不要同时让相机内参、marker 尺寸、全部 marker 位姿和地图尺度完全自由。至少固定物理 marker 边长和一个 Atlas gauge。

### 阶段 B：确定性前景排除

在分配 ORB 特征配额之前排除：

- 手部区域；
- 腕带及腕带 marker；
- 固定 marker 的内部图案区域（marker 四角由独立因子处理）；
- 明确的图像边缘坏区、反光过曝区和严重模糊区。

此阶段只使用便宜且高确定性的规则。不能因为自标定尚未收敛产生的重投影误差而过早删除大量背景点。

### 阶段 C：每序列局部建图

每条序列先独立运行原生 ORB-SLAM3：

- marker 可见时优先获得米制 pose seed；
- 背景地图点仍需真实视差、正深度和多视图三角化；
- marker 不可见时允许普通单目初始化；
- 短暂失跟使用原生重定位；
- 持续失败时创建新的 Atlas 子图；
- 不插值失跟帧，不用最后位姿冒充当前测量。

关键帧不是按固定频率插入，而应由以下信息增益决定：

- 足够平移或旋转；
- 当前可见地图点比例明显下降；
- 出现此前未覆盖的观察方向或距离；
- 首次可靠看到一个静态 marker；
- 新关键帧能显著增加地图覆盖或合图证据。

位置和视角近似重复的关键帧必须剔除。多序列的目标是增加视角多样性，不是增加冗余帧数量。

### 阶段 D：Marker 优先的跨序列候选

若两个子图多帧观察到同一静态 marker：

1. 从各自 marker 角点与相机位姿估计子图间变换；
2. 使用多帧中位数或鲁棒优化获得初值；
3. 检查尺度、旋转、正深度、四角重投影和跨帧一致性；
4. 生成 `merge candidate`，但暂不提交；
5. 在变换预测的重叠区域内搜索 ORB 支持。

单个弱 marker、边界受损 marker 或平面 PnP 歧义观测不能独立触发合图。它们可以作为分支投票或低权重残差参与已有候选的验证。

### 阶段 E：ORB 场景识别与几何验证

候选来源包括：

- 共同 marker 指向的局部区域；
- ORB BoW 数据库返回的相似关键帧；
- 已对齐轨迹附近的局部关键帧；
- 既有 Atlas 的重定位候选。

验证依次执行：

1. 描述子互检和比例测试；
2. 空间均匀性检查，避免内点集中在小区域；
3. 本质矩阵、单应矩阵竞争或 2D–3D PnP；
4. 正深度、视差和重投影残差检查；
5. 多关键帧连续支持；
6. 与 marker 预测和尺度状态的一致性检查。

重复纹理、平行走廊或相似工位必须要求更强的多帧证据。视觉验证失败时保留两张独立地图。

### 阶段 F：轨迹邻近候选

只有当两个子图已经通过 marker 或 ORB 粗略对齐后，才能使用轨迹邻近关系：

- 构建相机轨迹空间索引；
- 查找位置和观察方向接近的轨迹片段；
- 只在这些局部片段之间尝试 ORB 重匹配；
- 轨迹邻近只提高搜索效率，不增加约束权重；
- 最终关系仍必须通过图像几何验证。

这样可以避免对所有序列关键帧执行两两匹配，也避免错误轨迹形成自证循环。

### 阶段 G：分层优化与原子提交

建议三层优化：

1. **局部 BA**：优化当前关键帧、局部地图点和可见 marker；
2. **子地图位姿图**：以子图和静态 marker 为节点，优化跨会话 `SE(3)/Sim(3)`；
3. **周期性全局 BA**：仅在批处理、夜间或重要尺度/合图事件后执行。

固定 marker 应以已知尺寸、位姿可优化的刚性地标存在；一个参考 marker 或参考地图固定 gauge，其他远距离 marker 可在约束下调整。优化因子包括：

- ORB 地图点重投影；
- marker 四角重投影；
- 已验证视觉回环；
- 子图合并变换；
- 相机内参先验（自标定模式）；
- 鲁棒损失和观测质量权重。

候选优化必须在临时副本上执行。只有同时满足以下条件才提交：

- marker 和背景重投影残差下降或不显著恶化；
- 正深度比例合格；
- 尺度在合理范围；
- 原有可靠锚点没有被破坏；
- 没有产生大范围非物理轨迹跳变；
- 支持证据来自多个关键帧而非重复计入同一观测。

失败时完整回滚并记录原因。

### 阶段 H：动态与长期静态点迭代

地图点分为：

- `persistent`：跨帧、跨序列、跨视角保持一致，可进入长期 Atlas；
- `session-local`：只在当前序列可靠，暂不用于跨序列合图；
- `dynamic/suspect`：与背景运动或跨序列位置不一致；
- `bad`：三角化、描述子或重投影质量失败。

第一轮粗对齐后，根据以下证据更新地图点权重：

- 地图投影残差；
- 前后向光流一致性；
- 局部运动是否与相机背景模型一致；
- 多序列是否在相同世界位置重复观察；
- 语义无关的手/腕带几何遮罩；
- 同一区域是否在不同会话中发生结构变化。

第一轮只降低可疑点权重，不立即删除。完成一次优化后，再删除持续冲突的点并重新匹配。默认最多迭代 1–2 次；收益不足时不增加更多循环。

当前静止但未来可能移动的物体可以暂时作为 `session-local`；当后续序列显示其位置发生变化时再降级，不要求第一次观察就正确预测未来动态性。

## 7. Atlas 的长期使用方式

### 7.1 建图阶段

- 每个工位录制 2–4 条慢速扫描序列；
- 覆盖不同方向、距离、高度和常见遮挡；
- 相邻区域最好共享至少一个 marker 或稳定自然特征区域；
- 工位间走廊可以依靠 ORB 连续轨迹，工作区由 marker 保证米制精度；
- 地图建立完成后执行关键帧和地图点压缩。

### 7.2 正式采集阶段

- 现场只需录制原始高帧率视频；
- 在线可按 30–45 Hz 做预览、质量提示和粗定位；
- 最终使用完整视频、最终标定和最新 Atlas 离线重算；
- 新视频优先定位到既有 Atlas；
- 只有出现真正新区域时才建立临时子图；
- 临时子图经离线验证后决定合并或保持独立。

### 7.3 环境变化

- 不直接覆盖旧 Atlas；
- 记录地图版本、点的生命周期和变化事件；
- 将稳定结构与会变化的设备/物体分层保存；
- 新旧地图冲突时先创建新 revision；
- 只有通过跨会话验证后才淘汰旧点；
- 必须能够回放一次合图、尺度修正和点删除发生的原因。

## 8. 性能设计

朴素地对所有视频和全部地图点反复执行全局 BA 会不可扩展。推荐：

- 各序列的解码、marker、ORB 和手部分析并行执行；
- 观测缓存只计算一次，参数消融复用缓存；
- Atlas 按工位和连通区域分区；
- BoW、marker 和轨迹空间索引先筛选候选，禁止全部关键帧两两匹配；
- 日常更新只优化相关子图和共视邻域；
- 周期性全局 BA 在后台批处理；
- 对重复关键帧和重复地图点主动压缩；
- 定位时只加载当前附近局部地图；
- 内参收敛后锁定，避免每次局部 BA 重复优化。

实时线程不承担完整多会话建图。推荐职责分离：

| 模块 | 现场/在线 | 后台/离线 |
|---|---:|---:|
| 原始视频录制 | 全帧 | — |
| 质量预览 | 低频 | 可复核 |
| ORB 粗定位 | 30–45 Hz 可选 | 全帧最终处理 |
| Marker 检测 | 30–45 Hz 可选 | 全帧精确检测 |
| 手部检测 | 可关闭或低频 | 完整批处理 |
| 自标定 | 仅显示进度 | 完整优化 |
| 跨序列合图 | — | 后台 |
| 动态点迭代 | — | 后台 |
| 全局 BA | — | 周期性后台 |

- `persistent/session-local/dynamic/bad` 状态；
- 被替换、合并或删除的事件；
- 当前 Atlas revision。

## 10. 建议接口

具体命名可在实现时调整，但应保持职责清晰：

```bash
# 将视频分析为独立 session/submaps，不立即污染正式 Atlas
build_session_map VIDEO --atlas-base ATLAS --output SESSION_DIR

# 生成并验证跨序列候选
propose_session_merges SESSION_DIR ATLAS --marker-first --orb-verify

# 提交已验证的合图并执行相关子图优化
merge_session_map SESSION_DIR ATLAS --atomic --save-new-revision

# 跨会话静态一致性整理
refine_atlas_static_points ATLAS --iterations 1

# 对新动作视频只定位或选择性补图
localize_actions VIDEO --load-atlas ATLAS --mapping-mode selective
```

所有命令必须：

- 不覆盖输入 Atlas；
- 输出新 revision；
- 保存候选、验证、提交或回滚原因；
- 支持从观测缓存重跑；
- 区分算法输出和历史兼容读取。

## 11. 分阶段实现路线

### Milestone 0：固定基线

- 保存当前单序列系统的可恢复 milestone；
- 固定测试视频、标定、marker 配置和评价脚本；
- 定义 Atlas/session/submap ID 与 revision 规则；
- 建立单序列结果不可回退测试。

### Milestone 1：共同 marker 的多序列合图

- 每条序列独立建图；
- 同一静态 marker 生成跨序列候选；
- 多帧 marker 残差验证；
- 米制地图使用 `SE(3)` 合并；
- 相关子图 BA；
- 原子提交和失败回滚。

这是实用收益最高、依赖最少的第一版。

### Milestone 2：ORB 跨序列验证和补充连接

- 建立跨 session BoW 检索；
- marker 引导局部 ORB 重匹配；
- 无共同 marker 时允许纯视觉候选；
- 多关键帧几何验证；
- 重复地图点融合和关键帧剔除。

### Milestone 3：轨迹邻近搜索与局部加载

- 对已对齐轨迹建立空间/方向索引；
- 仅在局部邻域搜索额外回环；
- 工位级地图分区和按需加载；
- 测量搜索耗时、内存和误匹配率。

### Milestone 4：跨序列静态一致性

- 增加 `persistent/session-local/dynamic` 点状态；
- 使用重投影、光流和跨序列复现性降低动态点权重；
- 一次再匹配和联合 BA；
- 只有消融显示收益且开销合理时默认开启。

### Milestone 5：机会式相机自标定

- 标称 FOV 粗初始化；
- marker 视角/倾角/画面覆盖门控；
- 内参不确定性估计；
- 收敛后锁定并重处理；
- 严格比较专门标定、粗内参和机会式标定。

### Milestone 6：长期 Atlas 与工厂验证

- 多天、多操作者、多相机增量采集；
- Atlas revision 和环境变化管理；
- 未参与建图的新动作视频盲测；
- 可选机器人模仿学习/轨迹复现实验。

## 12. 验收与消融

### 12.1 必测对照

1. 单序列 ORB 地图；
2. 多序列仅点云堆叠（负面对照）；
3. 共同 marker 合图；
4. marker + ORB 几何验证；
5. 加轨迹邻近候选；
6. 加跨序列动态/静态筛选；
7. 专门相机标定与机会式标定。

### 12.2 核心指标

- 新序列首次定位成功率和耗时；
- 世界相机位姿有效率；
- 失跟次数、失跟总时长和重定位延迟；
- ATE、RPE 和米制尺度误差；
- 静止相机/腕部轨迹散布；
- 错误合图率与正确合图率；
- marker 和背景重投影误差；
- 关键帧、地图点和 Atlas 文件增长；
- 视频分钟/处理分钟；
- 峰值内存和局部地图加载时间；
- QC 后有效相机、左腕、右腕和双腕标签分钟数。

### 12.3 最关键实验

使用 1、2、4 条独立序列构建同一工位 Atlas，再对完全未参与建图的新操作者、新动作视频进行定位。预先固定评价协议，观察：

- 视角覆盖增加是否提高定位有效率；
- 失跟持续时间是否下降；
- 误差是否改善或至少不恶化；
- 收益在多少条序列后趋于饱和；
- 计算和地图大小增长是否可接受。

只有这一实验成立，才能证明多序列不是简单增加数据量，而是真正提高了地图复用和定位鲁棒性。

## 13. 风险与防护

| 风险 | 防护 |
|---|---|
| 同一 marker ID 被贴在多个位置 | 部署登记、冲突检测、禁止自动合并 |
| 平面 PnP 翻转导致错误候选 | IPPE 双解、多帧预测、ORB 几何验证 |
| 重复工位导致视觉混淆 | marker 身份、多关键帧支持、方向与残差检查 |
| 轨迹错误形成自证循环 | 轨迹只提候选，不成为独立约束 |
| 初始内参不准导致误删静态点 | 先 marker 粗标定，动态点先降权后删除 |
| 多序列导致关键帧爆炸 | 视角/覆盖驱动插入，重复关键帧剔除 |
| 全局 BA 过慢 | 工位分区、局部 BA、位姿图、后台周期优化 |
| 场景变化污染长期地图 | session-local 点、revision、生命周期管理 |
| 弱 marker 污染尺度 | 弱码仅辅助验证，不独立初始化或定尺度 |
| 合图失败破坏已有 Atlas | 临时副本优化、统一验证、原子提交、可回滚 |

## 14. 论文定位建议

### ICRA 版本

重点保持在低负担单目 ego 示教采集：无源双腕星座、稀疏工位 marker、米制 Marker–ORB Atlas、尺度再锚定、相机和双腕标签。

### T-RO 扩展方向

可将本方案发展为：

> A passive-anchor, multi-session and multi-camera lifelong metric Atlas for scalable egocentric robot demonstration capture.

T-RO 版不能只是增加视频和实验，应形成独立的新研究问题：多个无需同步、不同相机和不同时间的 ego 序列，如何在动态工厂环境中持续构建、验证、压缩和复用统一米制 Atlas，并将地图鲁棒性转化为更高的动作标签产出和机器人学习收益。

建议新增实质内容：

- 多序列增量地图融合；
- 多相机机会式自标定；
- 长期静态点与会话局部点建模；
- 地图版本、变化检测和回滚；
- 多工位、多天、多操作者盲测；
- 至少一个机器人模仿学习或轨迹复现实验。

## 15. 奥卡姆剃刀式优先级

实现时按收益/风险排序：

1. 共同 marker 合图与已有 Atlas 重定位；
2. ORB 跨序列几何验证；
3. 关键帧和重复地图点整理；
4. 轨迹邻近候选搜索；
5. 一次跨序列静态一致性迭代；
6. 机会式相机自标定；
7. 更复杂的多轮联合优化。

每一级必须单独做消融。复杂模块只有在以下至少一项有稳定收益时才默认启用：

- 定位有效率明显提高；
- 失跟时间明显下降；
- 误差明显下降；
- 处理或地图存储成本明显降低。

没有稳定收益的模块保留为实验开关，而不是成为默认链路。

## 16. 一句话总结

该方案不是把多个 ORB 点云简单相加，而是以静态 marker 建立米制跨会话骨架，以 ORB 几何确认真实场景重叠，以轨迹邻近提高搜索效率，再利用跨序列持久性剔除不稳定地图点，最终形成可以被不同操作者、相机和任务长期复用的版本化米制 Atlas。
